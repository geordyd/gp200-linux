# GP-200 Linux full-image recovery

If an attempt stops, retain its original library, journals and recovery history.
The app blocks ordinary device editing while unresolved recovery holds remain.
A stop request ends host work; it cannot guarantee that the pedal returned to
normal or undo a write. Do not edit journals or remove a hold to restore editing.

Open Assets → Firmware → History & recovery in the same original local library.
Select the supported official GP-200 V1.8.2 image and review a new full-image
recovery. The app must validate all unresolved local predecessors and the current
target binding. Imported, missing, altered or ambiguous history blocks admission.
Historical approvals cannot authorize a new attempt.

Recovery uses a separately approved fresh boot identity query and a new transfer
review with the actual current chunk and complete image. It starts at selector
00, block zero. There is no journal resume, automatic retry or speculative finish
command. This workflow supplies no reset, power-cycle or cable procedure.

The finite host limits are 900 seconds for approval, 60 seconds for transition
and 3,600 seconds for transfer. Per-action write/drain and reply limits remain
10 seconds. These limits are not a completion promise or measured device timing.
A wrong reply, uncertain write, reader loss, journal error, target change or
expired deadline stops the attempt and retains recovery state.

A completed final host write is only host-finished-unverified. The app requires
fresh normal identity/current/globals, actual reader/output retirement, a fresh
manual pedal-display report of V1.8.2, original store return and durable linked
closure before editing becomes available. Installed contents need separate
verification. Use the official Valeton support guidance when arranging any
vendor recovery procedure; it is not an automatic Linux byte retry.
